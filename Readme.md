## ✨ What is this?

**AI Software Architect** is a full-stack AI application that takes a plain-text software project idea and automatically produces a structured architecture package.

For example:

> 💡 **"Build a food delivery platform that supports 1 million users."**

The system analyzes the idea and generates:

- 📋 Functional & non-functional requirements
- 🏗️ System architecture
- 🗄️ Database design
- ⚙️ DevOps recommendations
- 📐 17 engineering diagrams
- 💾 Persistent project history
- 🖼️ PNG exports of generated diagrams

The architecture is generated by multiple specialized AI agents coordinated by a Spring Boot backend.

## 🧠 AI Agent Architecture

Instead of using one large AI prompt, the application divides architecture generation into specialized roles.

### 📋 Requirement Analyst

Generates:

- Functional requirements
- Non-functional requirements

### 🏗️ System Architect

Generates:

- Architecture pattern
- Core services
- Important REST endpoints

### 🗄️ Database Architect

Generates:

- Database tables
- Relationships
- Indexing recommendations

### ⚙️ DevOps Planner

Generates:

- Test cases
- Security risks
- Mitigation strategies
- Deployment/build timeline

All four agents are coordinated by:

```text
OrchestrationService
        │
        ├── RequirementAnalystAgent
        ├── SystemArchitectAgent
        ├── DatabaseArchitectAgent
        └── DevOpsPlannerAgent
```



## ⚡ Running Locally

### Prerequisites

- Java 17
- Python 3.x
- Node.js
- PostgreSQL
- Docker Desktop
- Google Gemini API key

### 🐳 Docker Compose

The easiest option is to run the complete application with Docker.

```bash
git clone https://github.com/pushpkumar-2602/ai-software-architect.git

cd ai-software-architect

export GEMINI_API_KEY="your_api_key"

docker-compose up --build
```

Open:

```text
http://localhost:5173
```

---

### 🐍 Run ML Service

```bash
cd ml-service

python3 -m venv venv
source venv/bin/activate

pip install -r requirements.txt

python classifier/train.py

python3 -m uvicorn app:app --host 0.0.0.0 --port 8000 --reload
```

### ☕ Run Backend

```bash
cd backend

./mvnw spring-boot:run
```

### ⚛️ Run Frontend

```bash
cd frontend

npm install
npm run dev
```

## 🔄 Request Flow

When a user generates an architecture:

```text
1. User enters project description
              ↓
2. Frontend creates project
              ↓
3. Backend stores project in PostgreSQL
              ↓
4. OrchestrationService starts
              ↓
5. Requirement Agent → Gemini
              ↓
6. System Architect → Gemini
              ↓
7. Database Architect → Gemini
              ↓
8. DevOps Planner → Gemini
              ↓
9. Results combined
              ↓
10. ArchitectureResult saved
              ↓
11. Result returned to frontend
              ↓
12. User can generate diagrams
              ↓
13. Mermaid renders diagrams
              ↓
14. Diagrams can be saved/revisited/exported
```

## 🧩 Engineering Decisions

### Generic Diagram Agent

Instead of creating 17 separate classes, the project uses:

```text
DiagramAgent
      +
DiagramTypeRegistry
```

This makes adding another diagram type simple and keeps the architecture maintainable.

### Sequential AI Agents

The four main agents currently run sequentially.

This keeps the first implementation simple and avoids creating unnecessary concurrent Gemini requests, especially under free-tier rate limits.

### Mermaid.js

Gemini generates Mermaid syntax directly, allowing one rendering library to support many diagram types.

### Environment-Based Configuration

Service URLs are configurable through environment variables with localhost defaults for development.

This allows the same codebase to work locally, in Docker, and in production.

## ⚠️ Current Limitations

The project is functional and deployed, but several areas are intentionally incomplete:

- 🔐 No authentication or authorization
- 👤 No per-user project isolation
- 🧠 ML classifier is currently independent from the main generation pipeline
- 📄 Only PNG diagram export is implemented
- 🧪 No automated unit/integration test suite yet
- ⚡ Core agents currently run sequentially
- 🏗️ Backend REST endpoints are currently grouped in one controller
- 📑 Project history does not currently use pagination
- 💤 Render free-tier services can sleep after inactivity
